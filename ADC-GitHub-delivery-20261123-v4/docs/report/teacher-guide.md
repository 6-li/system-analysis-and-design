# 教师操作与功能检验指南

本指南用于已部署的课程演示系统。建议先走通“患者预约→前台核验→到诊→医生诊疗→账单→模拟结算”，再查看排班、库存与季度经营功能。演示使用合成资料，结算不会真实扣款。

## 1. 进入系统与切换岗位

- 员工网页：打开提交者提供的演示网址，使用对应岗位账号登录。顶部显示当前岗位，左侧显示该岗位可用入口。需要其他岗位时，退出当前账号后重新登录。
- 患者小程序：使用提交者提供的体验二维码；若提示无体验权限，请由提交者添加体验成员。进入后注册或登录患者账号。
- 网页地址、体验二维码及密码由提交者通过课程指定方式单独提供，不放在公开仓库。

| 岗位 | 用户名 | 主要检验内容 |
| --- | --- | --- |
| 前台接待 | `reception` | 患者核验、正式预约、改约取消、到诊与未到诊 |
| 接诊牙医 | `dentist` | 本人日程、健康资料、沟通同意、多项目诊疗、临床费用核实 |
| 收费人员 | `billing` | 账单、费用疑问、确认与模拟结算 |
| 采购人员 | `procurement` | 采购需求、供货情况、验收入库 |
| 诊所负责人 | `manager` | 库存、耗用、费用异常补正、接诊安排草案及生效 |
| 总部运营 | `operations` | 季度统计、补正一致性检查、经营与牙医业绩核算 |
| 财务人员 | `finance` | 指定核算版本的财务复核 |

患者账号在小程序注册，不属于上述7个员工账号。门店81001用于主流程演示；81002可用于查看双店统计，不要求其已有诊疗记录。

## 2. 主流程：从预约到模拟结算

### 第一步：患者提交预约需求

1. 小程序登录后进入“预约就诊”，按页面填写本人信息。
2. 选择门诊、医生、日期和项目，查询并选择可用时段。
3. 核对预计占用时间，勾选本次选择确认，点击“提交预约需求”。
4. 进入“我的预约”查看申请办理进度。

**应看到：**稳定的申请回执及待核验/待办理进度。提交需求不等于正式预约成功，查询空闲时段也不预占名额。

初次使用若提示需完善或核验本人资料，按提示补充后由前台核验。尚未核验的账号不能直接读取正式患者档案。

### 第二步：前台核验并确认正式预约

1. 使用 `reception` 登录，在预约申请待办中查找刚提交的申请，点击“核验并办理”。
2. 核实患者身份。未建档时走核验建档；已有档案时查询并确认关联，避免重复建档。
3. 对本人账号完成必要的核验绑定；填写实际核验依据，不直接把自填资料当成核验通过。
4. 核对医生、诊所、时段和当前可用性，确认申请人接受方案后办理预约。
5. 保存后记下回执中的**预约编号**，患者在小程序刷新查看结果。

**应看到：**正式预约编号、时段及待到诊状态；小程序显示真实办理结果。若被拒绝，应能看到拒绝原因，且不会生成正式预约。

也可由前台直接进入“预约与到诊工作台”，选择“新建预约”，按页面先核实患者及接诊方案再提交；人工渠道不要求先有小程序申请。

### 第三步：前台登记到诊

1. 在前台“预约与到诊工作台”输入本次预约编号，点击“查询预约”。
2. 核对患者、预约安排及当前状态，选择“登记到诊”，按页面填写到诊核实信息并提交。
3. 重新查询，核对预约与关联就诊。

**应看到：**预约已到诊，并显示关联的**就诊编号**和实际接诊医生。

> 申请编号、预约编号、就诊编号、账单编号含义不同，不要求数字相同。后续操作以页面关联结果为准，不猜测编号。
>
> 若提前办理了未来预约的到诊，医生按登记日期查询时应使用实际登记日期，不能只按预约日期寻找。也可优先使用医生端的预约编号定位入口。

### 第四步：医生记录诊疗

1. 使用 `dentist` 登录，先查看本人日程与到诊患者。
2. 用前台回执中的预约编号定位关联就诊，核对患者及“预约→就诊”关系后使用该就诊。使用页面列表中的健康资料、沟通同意、实际诊疗入口可带入上下文。
3. 查询健康资料，按实际核实情况登记本次变更。
4. 进入“诊疗同意结果”，填写沟通对象，选择本次项目（可多选）、治疗范围及实际同意结论；需要监护人参与时填写参与情况，保存。
5. 进入实际诊疗，选择本次同意范围内的项目，按项目填写实施情况、数量、患者可见的问题说明及后续注意事项，再保存。可继续登记其他项目。

**应看到：**已保存的沟通记录、诊疗记录编号及版本，多项诊疗可归属于同一次就诊。未实施项目保留真实说明，不作为已实施项目收费。

患者随后在小程序“就诊记录”进入本次详情，可查看实际项目、接诊信息及医生填写的可见说明；内部员工备注不在患者端展示。

### 第五步：生成账单并模拟结算

1. 使用 `billing` 登录“账单与结算”，点击“查看待出账就诊”。
2. 选中本次就诊，点击“生成或查看账单”。
3. 核对项目、单位、数量、单价、小计和总额。金额按页面要求保留两位小数。
4. 点击“核对无误，进入模拟结算”，核对账单编号与当前版本，填写申请人、确认金额和确认依据。
5. 点击“发起或查看模拟交易”，再按交易页面提示完成结果核验及保存。
6. 返回工作台选择“全部”或“已结算”，刷新并查看详情。

**应看到：**账单逐项明细、模拟交易结果及已结算状态。患者小程序刷新就诊详情后可查看账单与模拟结算记录。仅发起交易不等于结算已完成。

如存在费用疑问，在费用疑问入口登记类型与说明。项目或数量问题由原接诊医生核实；收费人员依据核实结果处理账单，取得当前版本的再次确认后结算。不要拿旧版本确认去结算新版本。

## 3. 其他功能怎么检验

| 功能 | 操作步骤 | 预期结果 |
| --- | --- | --- |
| 改约 | 小程序查看本人预约并提交改约申请；前台核验原预约、重新选择有效安排后正式办理 | 正式办理前原预约保留；办理成功后同一预约显示新时段 |
| 取消 | 小程序提交取消申请，或由前台核实取消意愿后办理 | 正式取消后显示已取消，释放相应占用；拒绝申请不等于取消预约 |
| 确认未到诊 | 另选已结束、未取消且未登记到诊的预约，由前台核实后选择“登记未到诊” | 保存真实未到诊结果；不拿已到诊的主流程记录做此检验 |
| 30分钟提醒 | 使用已更新的小程序，准备前台已确认、将在30分钟内开始的本人预约；打开首页或“我的预约” | 显示倒计时、时段和预约信息；前台每30秒刷新，关闭小程序不推送。此项需上传本次提醒更新版后检验 |
| 接诊安排草案与生效 | `manager` 进入“接诊安排维护”，选择授权诊所、牙医和时段，先“初检”再保存草案；按页面核对受影响预约后确认生效 | 保存草案不立即成为可预约资源；满足检查并确认生效后才供预约使用。避免直接改动仍有未处理预约的已用时段 |
| 库存及预警 | `manager` 进入“医疗用品库存及预警”，选择诊所和用品后查询 | 显示库存、阈值及预警结果 |
| 采购与入库 | `procurement` 登记负责人已确认的采购需求；交付后进入“医疗用品验收入库”，核对来源、数量及本次验收结果后保存 | 显示需求或入库回执；成功入库后再查询库存，可核对数量变化。无法供货按页面另记真实情况 |
| 实际耗用 | `manager` 输入用品、数量和实际发生时间，可用时间选择器或“使用当前时间”；填写依据，先“确认本次成本依据”再“保存实际耗用” | 显示耗用记录、成本及扣减后库存。时间和数量以页面有效校验为准；采用已配置的课程来源 |
| 季度统计 | `operations` 进入“季度运营数据汇总”，选择有演示业务的年份、季度和诊所，点击“生成统计预览” | 显示应收、模拟实收、费用、耗用成本、牙医业绩、预约指标及异常；可选择81001/81002比较单店与双店 |
| 费用异常补正 | 有费用异常时，`manager` 查询本店异常，提交已核实的费用值及依据；`operations` 对该补正执行一致性检查，再重新统计 | 保留补正历史、实际复核状态及新统计快照。需要使用已配置来源，不能随填依据冒充核实；无异常时可直接查看正常统计，不必制造异常 |
| 核算与财务复核 | `operations` 按季度和诊所查询历史记录，选择可核算快照并“使用此快照”，保存核算；`finance` 在本岗位选择对应核算版本，核对后复核 | 编号和范围自动带入；形成核算及对应版本的财务复核，未通过复核不冒充已完成 |
| 历史与报告导出 | 从季度历史列表选择已复核的核算版本，查看后导出可读报告，可通过浏览器打印保存PDF | 重新登录仍能找回记录；导出内容对应所选已复核版本，不要求记住手工编号 |

## 4. 结果找不到时怎么核对

- **医生端没有患者：**先确认前台已登记到诊、实际接诊医生为当前医生；用预约编号定位，或按实际登记日期查询，并检查列表是否还有后续页面。
- **收费端没有账单：**先点“查看待出账就诊”并显式生成账单；已结算记录在“全部”或“已结算”查看。
- **患者端没有正式记录：**核对本人绑定、前台是否完成正式办理，以及当前登录账号；仅有申请回执不等于已有预约或就诊。
- **季度记录找不到：**核对年份、季度及单店/双店范围，使用历史列表查找，不猜快照或核算编号。
- **按钮不可用：**先核对当前岗位、必填项、当前状态及版本；使用界面已有选择或查询入口，不随意填写其他业务编号。
- **网络中断、会话过期或保存结果待核对：**先重新登录、查询原记录或回执，确认结果后继续，不反复新建同一业务。

## 5. 检验范围

各步骤以页面实际回执为准。主流程操作会新增课程演示数据，建议另建本次演示预约，并记下系统返回的关联编号；历史记录可只读查看。站内提醒不提供后台微信推送；患者小程序当前为本人账号范围；季度补正当前针对受控运营费用来源；支付采用模拟结算。

本指南不要求教师执行SQL、安装脚本或修改服务器配置。本地构建步骤另见[构建与运行](build-and-run.md)。
